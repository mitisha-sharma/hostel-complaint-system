3. DATABASE MODELS
================================================================================

3.1 USER Model (User.js):
Fields:
  - id, name, email, password (hashed with bcrypt)
  - role (student, admin, maintenance)
  - room_no (for students)
  - department (for maintenance staff - Electrical, Plumbing, etc.)
  - contact
  - isActive, timestamps

Features:
  - Password auto-hashing on save
  - comparePassword() method for authentication
  - Unique email constraint

3.2 COMPLAINT Model (Complaint.js):
Fields:
  - complaint_id, category (Electrical, Plumbing, Carpentry, etc.)
  - description, priority (Low, Medium, High, Critical)
  - status (Raised, Assigned, In Progress, Resolved, Rejected)
  - student_id, student_name, room_no
  - staff_id, staff_name, resolution_notes
  - assignedDate, resolvedDate, timestamps

Features:
  - References User model for student and staff assignments
  - Tracks complete complaint lifecycle
  - Audit timestamps for created and updated dates

4. API ENDPOINTS
================================================================================

4.1 AUTHENTICATION ENDPOINTS:
POST /api/auth/login
  Request: { email, password }
  Response: { token, user object }
  
POST /api/auth/register
  Request: { name, email, password, role, room_no(optional), department(optional) }
  Response: { token, user object }

4.2 COMPLAINT ENDPOINTS (Protected):
POST /api/complaints/raise (Student Only)
  Request: { category, description, priority }
  
GET /api/complaints (All authenticated users)
  Response: Filtered by user role (student sees own, staff sees assigned, admin sees all)
  
GET /api/complaints/:id (All authenticated users)
  Response: Complaint details
  
PUT /api/complaints/:id/assign (Admin Only)
  Request: { staff_id, staff_name }
  
PUT /api/complaints/:id/status (Staff/Admin)
  Request: { status, resolution_notes }
  
PUT /api/complaints/:id/reject (Admin Only)
  
GET /api/complaints/stats/overview (Admin Only)
  Response: Total, resolved, assigned, in-progress counts, statistics

4.3 USER ENDPOINTS (Protected):
GET /api/users (Admin Only)
  Response: All users (passwords excluded)
  
GET /api/users/role/:role (Admin Only)
  
GET /api/users/profile/me (All authenticated)
  Response: Current user profile

4.4 STAFF ENDPOINTS (Protected):
GET /api/staff (Admin Only)
  Response: All maintenance staff
  
GET /api/staff/department/:department (Admin Only)
  Response: Staff filtered by department

5. AUTHENTICATION & SECURITY
================================================================================

5.1 Authentication Flow:
1. User logs in with email/password
2. Backend verifies credentials against hashed password
3. JWT token generated with user ID, email, role, name
4. Token expires in 24 hours
5. Frontend stores token in localStorage
6. All protected routes require Bearer token in Authorization header

5.2 Authorization Middleware:
- authenticate: Verifies JWT token validity
- authorize: Checks user role for endpoint access
  - Students: Can only raise complaints, view own complaints
  - Admin: Full access to manage system
  - Maintenance: Can only view assigned complaints and update status

5.3 Security Features:
- Password hashing using bcrypt with salt rounds
- JWT token expiration (24 hours)
- Role-based access control (RBAC)
- Input validation on request data
- CORS enabled for frontend communication

13. TROUBLESHOOTING
================================================================================

Issue: Cannot connect to MongoDB
Solution: Ensure MongoDB is installed and running
  Command: mongod --version

Issue: Port 5000 already in use
Solution: Change PORT in .env file or kill existing process
  Powershell: Stop-Process -Port 5000 -Force

Issue: Backend cannot connect to frontend
Solution: Ensure CORS is enabled (already configured in server.js)

Issue: Token errors on API calls
Solution: Check localStorage for token after login
  Console: localStorage.getItem('token')

Issue: npm install fails
Solution: Delete node_modules and package-lock.json, then reinstall
  Command: rm -r node_modules package-lock.json & npm install
